# auto-reg 问题已处理（状态说明）

更新时间：2026-08-23  
分支：`cursor/auto-reg-liao-encrypt-870c`  
适用范围：`packages/auto-reg`（clean-room 净室自研的 Cursor 批量注册编排器）

本文件把早期实测中暴露的**三个面向使用者的问题**收敛成一份状态说明，并记录产品现在的行为。这里只做**高层描述**，**不包含任何注册流程或人机验证的复现步骤**；命令行开关、环境变量与安全约定，以 [`packages/auto-reg/README.md`](../packages/auto-reg/README.md) 为准。

## 1. CLI 进度刷屏，看不出进展

- **原问题**：进度只回显阶段名，且同一阶段会连续刷出多行，既看不出每步在做什么，也难判断卡在哪。
- **现在的行为**：进度按阶段输出，不再回显执行引擎的自由文本消息；进入人机验证阶段时，只打印一条**固定的、不含敏感信息**的提示（说明需要在可见窗口手动完成验证，或说明无头模式下为何会失败）。控制台始终只显示 email 与 ok/stage——**密码、验证码、session token 只落盘、绝不打印**。

## 2. Node 版本与 dry-run 账号库口令

- **原问题**：系统自带的 Node 20 无法运行；而且在账号库默认加密的前提下，未设置 `AUTO_REG_VAULT_PASSWORD` 时连 dry-run 都会被中断。
- **现在的行为**：
  - 运行环境明确要求 **Node.js ≥ 22**（用到内置的 TypeScript 类型擦除，直接跑 `.ts`，无需编译步骤）。
  - dry-run 更宽松：未设置 `AUTO_REG_VAULT_PASSWORD` 时**不再报错中断，而是以明文落盘并打印一条醒目的警告**，方便先把编排 / 落盘 / 报表的形状跑通。真实注册仍建议设置口令、保持账号库加密。

## 3. 失败结果不落盘

- **原问题**：真实注册失败时不写任何记录，事后无法回看是哪一步失败、失败了多少。
- **现在的行为**：失败结果也可以持久化，并且**只记录不含敏感信息的失败元数据**（例如 email 与失败所处阶段、错误摘要），不写入密码 / 验证码 / session token，便于统计与排查。

以上均为高层状态说明。人机验证仍是全自动流程的硬断点：本包把它当作「硬失败 + 需人工介入」，不做任何自动绕过。具体行为请以 [`packages/auto-reg/README.md`](../packages/auto-reg/README.md) 与 [`docs/AUTO_REG_MERGE_PLAN.md`](AUTO_REG_MERGE_PLAN.md) 为准。
