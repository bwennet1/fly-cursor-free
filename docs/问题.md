## 1. 无头真实注册卡在 Turnstile

```text
auto-reg register  count=1  dry-run=false  headed=false
  · init
  · identity
  · open_signup
  · open_signup
  · open_signup
  · submit_profile
```

之后长时间无输出；中断或超时后为失败，未写入 `accounts.json`。  
邮箱（liao.bot `@bwen.net`）能分配到地址；流程能走到提交资料；卡在人机验证相关阶段。

进程里曾同时出现：

- 二进制为 `chrome-headless-shell`
- 默认参数含 `--disable-extensions`
- 又传入 `--load-extension=…/packages/auto-reg/resources/turnstilePatch`

CLI 进度只打印 stage 名，连续多个 `open_signup` 看不出每步在做什么。

### 修复

- **真实注册默认自动 headed**：`dry-run=false` 时不再默认无头，无需显式传 `--headed`。确需无头可用 `--headless` 强制，但无头走 `chrome-headless-shell`，**无法加载 MV3 扩展**，且 Turnstile 只能人工点选、无头没有窗口可点——此时会在 `challenge` 阶段以 `CHALLENGE_REQUIRED` 明确失败并提示改用有头，而不是长时间无输出干等。
- **CLI 进度改为打印 `· <stage>  <脱敏消息>`**：引擎消息会先经 `sanitizeMessage`（抹掉 JWT / password= / 长 token / 独立 6 位码）再打印，连续多个 `open_signup` 也能看出每步在做什么。
- 失败不再「消失」：失败的尝试同样会写入账号库（密码 / token 已抹掉），详见第 3 节的修复说明。

## 2. turnstilePatch 与 vendor 加载方式不一致

本包落地目录：

```text
packages/auto-reg/resources/turnstilePatch/
```

vendor 里同一套扩展由 DrissionPage `add_extension` 加载，例如：

| 对照仓 | script.js | 谁加载 |
|---|---|---|
| `vendor/cursor-auto-free` | `turnstilePatch/script.js` | `browser_utils.py` |
| `vendor/wf-cursor-auto-free` | `turnstilePatch/script.js` | `browser_utils.py` |
| `vendor/cursor-auto-icloud` | `src/turnstilePatch/script.js` | `src/utils/browser_utils.py` |
| `vendor/cursor-auto-gui` | `resources/turnstilePatch/script.js` | `src/utils/browser_utils.py` |
| `vendor/cursor-free-vip` | `turnstilePatch/script.js` | `new_signup.py` |
| `vendor/zzxcursor` | `core/turnstilePatch/script.js` | `core/browser_manager.py` |
| `vendor/cursor-register` | `turnstilePatch/script.js` | `cursor_register.py` |

`cursor-register` 注释上游：  
https://github.com/TheFalloutOf76/CDP-bug-MouseEvent-.screenX-.screenY-patcher  

`any-auto-register` 无该目录，同类逻辑在 `platforms/cursor/browser_register.py`，注释指向：  
https://github.com/Xewdy444/CDP-bug-MouseEvent-.screenX-.screenY-patcher  

实测时：扩展目录已存在并被传给浏览器，但无头路径下 Turnstile 仍过不去；Continue 点击后长时间停在 `submit_profile`。

### 修复

- 真实注册默认自动 headed 后，默认路径与 vendor 的 DrissionPage `add_extension` 等价：用 `--load-extension` 加载 `resources/turnstilePatch`，并移除 Playwright 默认的 `--disable-extensions`。不再出现「`chrome-headless-shell` + `--disable-extensions` + `--load-extension`」三者矛盾并存的组合。
- 只有显式 `--headless` 才会回到 `chrome-headless-shell` 路径：该路径**无法加载 MV3 扩展**，仅以 `addInitScript` 注入 `script.js`，Turnstile 仍需人工完成，因此真实注册不再默认走这条路。

## 3. 其它环境问题

- 系统自带 Node 为 20，auto-reg 要求 Node ≥ 22。
- 默认开启账号库加密时，未设置 `AUTO_REG_VAULT_PASSWORD` 无法跑（含 dry-run）。
- 真实注册失败时不落盘；成功路径会写 `accounts.json`（本地敏感，勿提交）。

### 修复

- **Node 要求不变**：仍需 **Node ≥ 22**（`--experimental-strip-types` 直接跑 `.ts`）；系统 Node 20 需自行升级（如 `nvm install 22`）。
- **dry-run 缺口令不再报错**：dry-run 未设置 `AUTO_REG_VAULT_PASSWORD` 时，自动关闭本次运行的账号库加密并打印警告（明文落盘，仅供演练）；真实注册缺口令仍在校验阶段直接报错。
- **失败也落盘**：真实注册失败时也会把该次尝试追加进账号库（保留 email / stage / 错误信息，**密码与 token 已抹掉**），便于统计与排查；成功记录照常完整写入（本地敏感，勿提交）。
